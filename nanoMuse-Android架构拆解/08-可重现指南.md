# 第 8 章 可重现指南：构建、调试、测试与源码索引

> 本章让你能亲手验证前七章的每一个结论。构建步骤来自 `docs/android.md` "Building it yourself" 一节（已核对）。

## 8.1 获取与固定版本

```bash
git clone https://github.com/nano-muse/nanoMuse.git
cd nanoMuse
git log -1 --format='%H %ci'   # 固定你分析的 commit
```

本知识库基于 2026-11-17 的 main 分支快照（CHANGELOG 处于 1.0.x 之后的 Unreleased）。行号会漂移，**以函数名/类名为锚点**检索：

```bash
grep -n "private suspend fun runAgentLoop" android/src/android/app/src/main/java/com/openminis/app/ui/chat/ChatViewModel.kt
```

## 8.2 构建

前置：JDK 21（CI 同款）、Android SDK（Android Studio 会装好两者）；裸机可用 `scripts/android/env.sh` 配环境。

```bash
bash scripts/android/build-natives.sh   # 一次性：proot、Alpine rootfs、rclone.aar（NDK r27c、Go 1.25+）
cd android/src/android
./gradlew :app:assembleDebug            # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease          # 有 android/keystore.properties 时用其签名
./gradlew :app:testDebugUnitTest --tests 'io.github.nanomuse.*'
./gradlew :app:lintDebug
```

注意事项（官方文档载明）：
- 中国大陆网络先 `export GOPROXY=https://goproxy.cn,direct`（rclone.aar 的 Go 模块拉取）。
- lint 用比 AGP 8.7.3 自带更新的版本（gradle.properties 的 `android.experimental.lint.version`）；上游树自带 lint 发现，读报告时聚焦 `io.github.nanomuse`。
- `scripts/rebrand.py` 持有版本号并把 nanoMuse 命名应用到 OpenMinis 树；原生部分见 `android/BUILDING.md`。
- 无签名密钥时 release 用 debug key 签名，可安装但不能覆盖正式签名构建。
- rootfs 相关脚本：`android/scripts/{prepare_rootfs,install_alpine,optimize_rootfs,prepare_android_sandbox}.sh`。

## 8.4 调试与观测

- **logcat 标签**：`ToolChain[VM]`（工具链全生命周期：ToolUseStart/InputDelta/Complete/executeTool START/END/块状态迁移）、`TAG_STREAM`（runAgentLoop 进出、CtxShape 请求形状探针、空轮诊断）、`T-STALL-DIAG`（REQUEST-OUT/FIRST-CHUNK/NO-FIRST-CHUNK，含 TTFB）、`ToolPreflight`（拒绝原因 + 参数快照环 dump）、`ShellExecDiag`、`XSessionDiag`（记忆注入与会话关联）。
- **应用内调试**：`com/openminis/app/debug/{DebugRPCHandler,DebugInspectorMethods,DebugScreenshotRing}.kt`；`android/scripts/gen_debug_skill_android.sh` 生成调试技能。
- **审计**：guard 决策经 ClientEvents 上报（只有代码与数字，无命令/页面内容，docs/cloud.md#client-events）；minis-config 的写操作有 1000 条滚动可撤销审计（设置→日志→配置变更）。
- **复现一次完整轮次**：发一条会触发工具的消息，`adb logcat -s ToolChain[VM]` 即可看到 流事件→修复→熔断→preflight→执行→块状态 的全链路日志。

## 8.7 复用建议

想在自己的 Android Agent 项目里复用这套设计，按性价比排序：

1. **ToolLoopDetector**（独立类，无 Android 依赖，可直接移植）——四级策略 + tool_title 剔除 + 稳定哈希，是防跑飞的最小完整方案。
2. **ContextBudget + ContextTrimming**（纯 Kotlin，请求视图模式）——水位线公式与五阶段裁剪可直接搬。
3. **PersistentShell 标记协议 + 会话级并发**——任何需要长驻 shell 的移动端 Agent 都适用。
4. **RiskGate 审批队列 + 分级授权**——180s 超时即拒、warning 永不豁免、付钱绑屏幕锁，三条规则值得照抄。
5. **PromptCacheLayout**——稳定前缀/易变后缀的纪律，对任何按前缀缓存的模型服务都有效。

注意 GPL-3.0-or-later 的传染性：直接复制代码意味着你的项目也需 GPL 兼容开源；只借鉴设计思想不受限。

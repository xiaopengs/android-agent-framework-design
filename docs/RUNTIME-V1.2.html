三、三条主链路验证结果

链路 1 · LOCAL

3 轮 done，2 次工具调用

写文件 → shell 读回 → 收尾；事件流 turn_start / turn / tool_start / tool_result / text / done 齐全，五层事件（router_decision / task_enqueue / session_state / tool_dispatch）全部可见。

链路 2 · HYBRID

2 次 TOOL_CALL 闭环，0 死信

云端下发 → OffloadGate 越权校验 → 端侧同一条风控链路执行 → TOOL_RESULT 标准化回传 → STATUS FINISHED。bus_send / ack / inbound 齐全。

链路 3 · CLOUD

本地内核零启动

无 turn_start、无 tool_result、不创建 Sandbox、不入 TaskQueue，仅流式 STREAM_CHUNK 与状态信封。

安全专项：rm -rf 判 DESTRUCTIVE → 审批 DENY → 命令未执行、文件保留；断网自动降级 LOCAL；10 个独占工具 × 3 种请求组合均不输出 CLOUD。内置自检 31 项、端到端冒烟 18 项连续两次运行全绿。

六、剩余缺口（V1.3 建议）

  • 真实传输层：SimulatedCloudTransport 换 WebSocket / gRPC，与真实云端 Agent 服务联调。
  • 模型流式：Provider 接 SSE 增量解析并调 onText，循环层无需改动。
  • Android 平台 Handler：CalendarContract / NotificationManager / WebView（browser_use 的 click/input）、无障碍。
  • 隔离与授权：Sandbox 换 proot / bwrap；ApprovalGate 的会话级 / 永久授权态持久化与 UI 卡片。
  • 存储与事件：SessionStore → SQLite、EventSink → SSE/Hub、MemoryStore → 向量检索。
  • 工程化：上下文摘要模型化、多会话并发压测、长稳保活、MCP/A2A 真实传输 Server。
逐项对齐矩阵与验收对照见 runtime/COVERAGE.md；方案基线见 docs/DESIGN.md 第 16 章。所有验证均可在本机复现，不依赖真实模型密钥。
